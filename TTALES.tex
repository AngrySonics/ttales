\N{1}{11}Memory Manager.  Memory allocation  and
deallocation  is provided by these routines.
\PB{\\{AllocMem}} uses the first fit algorithm.  It does not initialize the
memory in any way.  FreeMem sorts the free list and merges adjacent
blocks.  No garbage collection or heap compaction is performed.
Information critical to the integrity of the memory management system is
stored immediately adjacent to allocated blocks.  If a client overwrites
the boundaries of an allocation, bad things will happen.

\fi

\M{15}\PB{\\{AllocMem}} proceeds in a simple manner.  First it scans the free
list
looking for a block that is at least as large as the client has requested,
plus overhead.  If it fails to find one, it returns \PB{$\NULL$}.  If it
succeeds, it decides whether it can produce a new free block from the
remnant.  If not, it returns the entire block to the client.  If so, it
cuts off a slice and gives it to the client.

\N{1}{79}Input/Output System Client Interface.   These are the macro

the various ways to invoke the I/O system from

directly cause the requested I/O to occur, they merely queue the request for
later handling.  They also do not test for buffer overflow, so the user must
assure that \PB{\\{IOBufferCapacity}} is sufficiently large.   The
buffer is circular, so if an overflow occurs it will not crash the program, but
it will lose many requests.

\N{1}{129}Co\"ordinate System Transformations.

To produce a VDP address from a square coordinate, we apply several
transforms.  Before we begin, let me define a few things.  Square coordinates
originate in the lower left, with $j$ increasing horizontally to the right,
and $i$ increasing diagonally to the upper right.  Cell coordinates also
originate in the lower left, with $x$ increasing to the right, but $y$
increases straight up, rather than diagonally.  The mapping between them is
defined by:$$x=4\cdot j + i$$ $$y = 2\cdot i + z$$The display
screen
has its vertical coordinate flipped.  The mapping from cell coordinates to
screen
coordinates is:$$\alpha=x$$ $$\beta=y_{max}-y$$From screen coordinates to
VDP coordinates is:$$\theta=\alpha\bmod 64$$ $$\phi=\beta\bmod 32$$The final
conversion is to a VDP address, as follows:$$addr=ScreenBase+128\phi+2\theta$$
Substitution doesn't really gain anything in terms of efficiency, so we
calculate as outlined above.  The values $\theta$ and $\phi$ are useful, while
we are drawing squares, to determine whether we have crossed the screen wrap
point in any direction as we draw these extended objects.

The conversion to screen pixel coordinates simply involves multiplying the
screen coordinates by eight. $$\alpha_p=8\cdot\alpha$$ $$\beta_p=8\cdot\beta$$
To go on to an actual sprite position,  $$h=\alpha_p-S_x+128$$
$$v=\beta_p-S_y+128+7$$
Where $S_x$ and $S_y$ are the screen fine scroll settings.
